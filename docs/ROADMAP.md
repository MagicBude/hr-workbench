# 产品路线图与愿景（ROADMAP）

> 本文件描述 hr-workbench 从 MVP 走向"成熟、可上市"通用人事系统的演进路径。  
> 与 `docs/PLAN.md`（实施节奏）、`docs/SPEC.md`（功能规格）配套。

---

## 1. 愿景

> **做一款零门槛、可私有部署、像大厂 HR 系统一样专业，却又轻量到一个人就能维护的通用人事工作台。**  
> 服务于中小公司、创业团队、代账机构，以及未来可能接入的更多企业。多组织、可扩展、数据自主。

### 对标能力（大厂 HR SaaS 共性）
- 员工全生命周期管理（入职→转正→调岗→离职）
- 复杂考勤规则（排班、节假日、调休、加班转调休、多时段）
- 精准薪资核算（五险一金按地区比例、个税、年终奖）
- 审批流与权限体系
- 数据看板与人力成本分析
- 开放 API 与生态集成

我们**不追求一次做全**，而是分阶段逼近，每一阶段都可独立交付、独立使用。

---

## 2. 成熟度模型

| 等级 | 名称 | 标志 |
|---|---|---|
| L1 | **MVP** | 花名册/考勤/薪资/看板四模块可用，localStorage 存储 |
| L2 | **完善** | 编辑/排序/调休/节假日/分时段/缴纳明细/Excel 导出（= Phase 1–5） |
| L3 | **专业** | 权限/审批/审计/BI 预警（= Phase 6–9） |
| L4 | **生态** | 开放接口/多币种/合同/异动/PWA/集团版（= Phase 10 +） |
| L5 | **可上市** | 后端多租户/SSO/安全合规/移动 App/商业支持 |

---

## 3. 阶段与目标

### 近期（L1→L2，打造好用的工具）
- **Phase 1 花名册增强**：编辑、序号、拖拽排序、可调休余额。
- **Phase 2 考勤重构**：国家节假日、自定义放假、上午/下午/加班三时段、星期显示、调休联动。
- **Phase 3 薪资缴纳明细**：公司/个人缴纳展示、组织与员工级比例。
- **Phase 4 Excel 导出**：花名册/考勤/薪资导出 `.xlsx`（本地 SheetJS）。
- **Phase 5 打磨**：旧数据迁移、移动端、性能、帮助提示。

当前 L2 收尾工作的详细优先级、验收口径与实施批次见 [`OPTIMIZATION_BACKLOG.md`](OPTIMIZATION_BACKLOG.md)。近期先完成数据正确性、员工生命周期、快照恢复、大表体验和自动化测试，再进入权限与审批阶段。

### 中期（L2→L3，像企业系统）
- **Phase 6 权限 RBAC**：超级管理员/HR/部门经理/员工自助。
- **Phase 7 审批流**：调休/请假/加班/薪资发放状态机。
- **Phase 8 审计与版本**：操作留痕、数据快照、回滚。
- **Phase 9 BI 预警**：人力成本趋势、离职率、异常考勤标红。

### 远期（L3→L4，平台化）
- **Phase 10 开放能力**：打卡机/财务/电子签适配器接口。
- 多币种薪资、合同管理、异动流程、PWA、集团版汇总看板。

### 上市准备（L4→L5）
- 后端多租户架构（替换 store.js 内部实现）。
- 单点登录（SSO）、数据安全合规（加密、备份策略）。
- 移动端 App、商业支持与文档体系。

---

## 4. 关键设计决策（支撑长期目标）

1. **数据层隔离**：接后端只改 `store.js`，业务模块不动 → 上市阶段不重写。
2. **零 CDN 依赖**：所有第三方库本地化 → 可私有部署、可离线。
3. **文档驱动**：PLAN/SPEC/STANDARD/ARCHITECTURE 四文档约束质量 → 多人可协作。
4. **增量交付**：每 Phase 独立可用、独立提交 → 风险可控、可随时回退。
5. **多组织隔离**：数据天然支持多公司 → 直接支撑集团版与 SaaS 化。

## 5. 成功指标（未来衡量）

| 维度 | L2 目标 | L5 目标 |
|---|---|---|
| 模块完整度 | 4 核心模块 + 导出 | 全生命周期 + 审批 + BI |
| 组织数/实例 | 演示级 | 支持多租户 1000+ |
| 数据规模 | 50 人 × 12 月流畅 | 万人级性能达标 |
| 部署方式 | GitHub Pages | 私有/云多部署 |
| 文档完备度 | PLAN/SPEC/STANDARD/ARCH | 完整 API + 用户手册 |

## 6. 开放问题（待产品决策）
