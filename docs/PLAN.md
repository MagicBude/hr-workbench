# HR Workbench 优化计划表（历史基线）

> 本文保留早期 Phase 1–10 的实施过程，便于追溯，不再作为当前数据结构和验收口径的权威来源。当前实现以 [`SPEC.md`](SPEC.md)、[`STANDARD.md`](STANDARD.md)、[`ARCHITECTURE.md`](ARCHITECTURE.md) 为准；最新优化状态与后续事项见 [`OPTIMIZATION_BACKLOG.md`](OPTIMIZATION_BACKLOG.md)。

> 目标：把当前 MVP 逐步升级为一个更完整、更易用、更像 Excel 的通用人事考勤薪资工作台。  
> 节奏：**分 5 个 Phase，每个 Phase 独立完成并提交一次 git commit**，方便随时回退和验收。

---

## 设计原则（贯穿全程）

1. **零运行时 CDN 依赖**：所有第三方库（如需要）都下载到本地 `vendor/` 目录，保证离线可用、可部署 GitHub Pages。  
2. **向后兼容**：旧数据在加载时自动升级到新的数据结构，用户之前导入的 `斯迈孚导入数据.json` 仍然可用。  
3. **可持续中文注释**：重点解释业务口径和设计原因，避免逐行翻译与阶段性补丁描述。
4. **数据层隔离**：所有结构变更都通过 `store.js` / `sample.js` 收敛，业务模块只读 `state.data`。  
5. **移动端优先**：表格在手机上可横向滚动，关键操作按钮不小于 44×44px。

## Phase 1：花名册增强（编辑、序号、拖拽排序、调休时间）

### 目标
让花名册从"只能新增+删除"升级为"可维护的员工档案"，并为调休功能打下基础。

### 数据结构调整

```js
// 员工对象新增字段
{
  id: "e_xxx",
  name: "张三",
  dept: "销售部",
  hireDate: "2026-03-01",
  baseSalary: 8000,
  // 新增
  restMinutes: 0,           // 可调休余额（精确到分钟）
  insuranceBase: null       // 社保公积金基数，null 表示用组织默认（baseSalary）
}
```

员工顺序不再按 id，而是按 `state.data.employees` 数组本身的顺序；拖拽排序即交换数组元素位置。

### UI 改动

- 表格列变为：`序号 | 姓名 | 部门 | 入职日期 | 基本月薪 | 可调休(小时) | 操作`
- 操作列增加"编辑"按钮，点击弹窗修改员工所有字段。
- 增加拖拽手柄（⋮⋮ 或 ≡），支持 HTML5 Drag & Drop 排序。
- 顶部添加"批量导入/导出花名册"按钮（为后续 Excel 导出做铺垫）。
- 在考勤模块中，选中"调休"状态时，如果该员工 `restMinutes < 240`（不足 0.5 天）给出提示，并显示剩余可调休时间。

### 涉及文件

- `js/config.js` — 增加"半天分钟数"等常量。
- `js/store.js` — 增加数据迁移函数，把旧 employee 结构升级出新字段。
- `js/sample.js` — 示例员工带上 `restMinutes`。
- `js/roster.js` — 重写渲染逻辑，增加编辑、序号、拖拽排序。
- `js/ui.js` — 增加通用"员工编辑弹窗"。
- `css/styles.css` — 拖拽态样式、编辑按钮样式。
- `index.html` — 花名册表头增加"序号"、"可调休"、"操作"列。

### 验收标准

- [ ] 新增员工后，行号自动从 1 开始递增。
- [ ] 点击"编辑"可修改姓名、部门、入职日期、基本月薪、可调休余额。
- [ ] 拖拽可改变员工顺序，刷新页面后顺序不变。
- [ ] 旧数据导入后自动出现"可调休 0 小时"，不报错。
- [ ] 考勤页选择"调休"时能看到剩余可调休时间提示。

## Phase 2：考勤表重构（节假日、分时段、星期、界面优化）

### 目标
让考勤表从"每天一个格子"升级为"每天分上午/下午/加班三时段"，并内置国家节假日，支持老板临时多放几天假。

### 数据结构调整

#### 1. 考勤记录

```js
// 旧结构（兼容）
rec: { 1: "√", 2: "事", ... }

// 新结构
rec: {
  1: { am: "√", pm: "√", ot: "" },   // 上午、下午、加班
  2: { am: "事", pm: "事", ot: "" },
  ...
}
```

加载旧数据时，把单字符自动转换为 "上午=下午=旧状态，加班=空"。

#### 2. 节假日

```js
state.data.holidays = {
  "2026-01-01": { name: "元旦", type: "holiday" },
  "2026-01-02": { name: "元旦", type: "holiday" },
  "2026-02-11": { name: "春节调休上班", type: "workday" }, // 调休上班日
  // ...
}
```

- `holiday`：休息日，默认不计入应出勤。
- `workday`：调休上班日，计入应出勤。

#### 3. 组织设置

```js
state.data.settings = {
  overtimeToRest: true,      // 加班是否自动转为调休
  overtimeToRestRatio: 1.0,  // 加班分钟 × 比例 = 增加的可调休分钟
  halfDayMinutes: 240        // 半天多少分钟（默认 4 小时 = 240 分钟）
}
```

### UI 改动

- 考勤表改为"表头两行"：第一行日期（1–31），第二行星期（一/二/三...）。
- 每个员工每天显示三行小格：`上` `下` `加`，分别点击切换状态。
- 节假日日期格自动标灰，并显示"休"或"班"小标签；老板临时多放的假可手动标记为 holiday。
- 右侧汇总列拆成多行：出勤天数、事假、病假、缺勤、调休、年假、加班小时。
- 增加"节假日设置"按钮，弹窗展示当月节假日列表，支持：
  - 一键"重置为 2026 年国家节假日"（内置数据）。
  - 手动添加/删除/修改某天为放假或上班。
- 当员工选择"调休"时，自动按 `halfDayMinutes` 扣减余额；选择"加班"且设置开启时，自动按时段增加可调休余额。

### 涉及文件

- `js/config.js` — 增加时段标识 `SHIFTS = ['am','pm','ot']`、2026 年国家节假日常量。
- `js/store.js` — 数据迁移：旧 `rec` 升级为新结构；初始化 `holidays`、`settings`。
- `js/sample.js` — 生成示例考勤时使用新结构；生成国家节假日。
- `js/attendance.js` — 完全重写渲染与交互逻辑。
- `js/roster.js` — 编辑弹窗增加可调休余额字段。
- `js/ui.js` — 增加"节假日设置弹窗"。
- `css/styles.css` — 新考勤表格样式（参考用户截图的 Excel 风格：蓝紫色表头、白色日期格、汇总列在右侧）。
- `index.html` — 考勤区增加"节假日设置"按钮、调整提示文案。

### 验收标准

- [ ] 打开 2026-01 考勤表，1 月 1–2 日自动显示为节假日（灰色+"休"）。
- [ ] 每个员工每天可独立设置上午、下午、加班状态。
- [ ] 旧数据导入后，原来的 "√" 会同时出现在上午和下午。
- [ ] 选择"调休"会自动扣减该员工 `restMinutes`；余额不足时提示。
- [ ] 选择"加班"且设置开启时，自动增加 `restMinutes`。
- [ ] 表头正确显示星期几，周末列用浅色背景区分。

## Phase 3：薪资缴纳明细与比例设置

### 目标
让薪资模块像真实工资条一样，展示"公司缴纳"和"个人缴纳"的每一项，并允许调整比例。

### 数据结构调整

员工对象已增加 `insuranceBase`（Phase 1），基数可用员工个人值或组织默认值。

组织设置增加比例配置：

```js
state.data.settings.insuranceRatio = {
  company:  { 养老: 0.16, 医疗: 0.08, 工伤: 0.002, 失业: 0.005, 生育: 0.008, 公积金: 0.12 },
  personal: { 养老: 0.08, 医疗: 0.02, 失业: 0.005, 公积金: 0.12 }
}
```

`payroll` 对象结构不变，但 UI 要展开显示 `comp` 和 `pers` 的每一项。

### UI 改动

- 薪资表头部增加"公司缴纳"分组列：养老、医疗、工伤、失业、生育、公积金。
- 薪资表头部增加"个人缴纳"分组列：养老、医疗、失业、公积金、大病医疗。
- 在薪资卡片顶部增加"社保公积金比例设置"按钮，点击弹窗：
  - 公司缴纳比例 6 项输入框。
  - 个人缴纳比例 5 项输入框（大病医疗为固定金额）。
  - "应用到当前组织"按钮。
- 在员工编辑弹窗中增加"社保基数"字段：默认空（用基本月薪），可填具体数字覆盖。
- 计算逻辑：`基数 = employee.insuranceBase || payroll.baseSalary`。

### 涉及文件

- `js/config.js` — 比例默认值保持不变，但增加"可设置项清单"。
- `js/store.js` — 初始化 `settings.insuranceRatio`。
- `js/sample.js` — 示例数据使用组织默认比例。
- `js/payroll.js` — `recompute()` 改用员工/组织比例；渲染增加公司缴纳和个人缴纳明细列；增加比例设置弹窗绑定。
- `js/roster.js` — 编辑弹窗增加"社保基数"。
- `js/ui.js` — 增加"比例设置弹窗"。
- `css/styles.css` — 表头分组样式（双层表头）。
- `index.html` — 薪资表表头改为双层结构。

### 验收标准

- [ ] 薪资表能清晰看到公司缴纳 6 项和个人缴纳 5 项。
- [ ] 修改组织比例后，点击"生成/刷新薪资"立即按新比例重算。
- [ ] 某员工设置社保基数为 5000 后，其五险一金按 5000 计算，其他人仍按基本月薪。
- [ ] 旧数据导入后比例使用默认值，计算结果不变。

## Phase 4：Excel 导出功能

### 目标
让用户可以直接导出 `.xlsx` 文件，格式接近最初提供的 Excel 表格，老板不用打开网站也能看。

### 技术方案

- 引入 [SheetJS](https://github.com/SheetJS/sheetjs) 的独立文件 `vendor/xlsx.mini.min.js`（下载到本地，不引用 CDN）。
- 新增 `js/export.js` 模块，封装三个导出函数：
  - `exportRosterXlsx()`：导出花名册（含序号、姓名、部门、入职日期、基本月薪、可调休余额、社保基数）。
  - `exportAttendanceXlsx(month)`：导出考勤表，格式参考用户截图：表头含日期+星期，每员工每天三行（上午/下午/加班），右侧汇总列。
  - `exportPayrollXlsx(month)`：导出薪资明细表，包含公司缴纳、个人缴纳、应发、个税、实发等全部列。
- UI 上：把原来的"导出 CSV"按钮改为下拉菜单或三个独立按钮：`导出花名册` / `导出考勤表` / `导出薪资表`。

### 涉及文件

- 新增 `vendor/xlsx.mini.min.js`（本地库文件）。
- 新增 `js/export.js`（导出逻辑）。
- `js/main.js` — 初始化导出按钮事件。
- `index.html` — 替换 CSV 按钮为三个导出按钮。
- `css/styles.css` — 按钮组样式。
- `README.md` — 说明新增了一个本地第三方库。

### 验收标准

- [ ] 点击"导出考勤表"生成的 `.xlsx` 能在 Excel/WPS 中正常打开，表头含日期和星期。
- [ ] 点击"导出薪资表"生成的 `.xlsx` 列与用户原始表格基本一致（姓名、入职日期、薪资起止日期、当月考勤、缺勤、实出勤、出差补贴、奖金、基本月薪、节假日加班费、本月应发、公司缴纳、个人应缴、应补退税额、实发薪资）。
- [ ] 点击"导出花名册"生成的人员清单可直接用于再次导入。
- [ ] 离线环境下（关闭外网）仍能导出，不依赖 CDN。

## Phase 6+：远期规划（向成熟 SaaS 靠拢）

以下能力已拆分进 `docs/ROADMAP.md`（产品愿景）与 `docs/SPEC.md`（详细规格），此处只列目标与触发条件。

### Phase 6：权限与多角色（RBAC）
- **目标**：系统区分「超级管理员 / HR / 部门经理 / 员工自助」四种角色。
- **触发**：多个公司或多人共用一个组织时。
- **关键点**：员工自助端只能看自己的薪资与考勤；部门经理可看本部门；HR 全权；敏感操作（改薪资）需二次确认。

### Phase 7：审批流引擎
- **目标**：调休申请、请假、加班、薪资发放都走"提交 → 审批 → 生效"流程。
- **触发**：企业有正式审批制度时。
- **关键点**：可视化流程（提交人 → 直属上级 → HR），状态机：`草稿 / 待审批 / 已通过 / 已驳回 / 已撤销`。

### Phase 8：审计日志与数据版本
- **目标**：关键操作（增删员工、改薪资、导数据）留痕，可追溯。
- **触发**：上规模后合规要求。
- **关键点**：导出 JSON 写入 `version` 字段；每次保存前打快照，支持"回到上一版"。

### Phase 9：BI 看板与预警
- **目标**：在月度看板之外，增加人力成本趋势、离职率、异常考勤预警。
- **触发**：数据积累到一定量。
- **关键点**：出勤率<80% 或连续缺勤 3 天自动标红预警；人力成本环比超 10% 提醒。

### Phase 10：开放能力与生态
- **目标**：预留对接打卡机、财务系统、电子签的接口。
- **触发**：需要与其他系统集成。
- **关键点**：在 `store.js` 预留 `importAttendance(records)` / `exportToFinance()` 等适配器接口；数据层抽象让后端接入只改一处。

### 其他已记录的好点子（详见 `docs/SPEC.md`）
- 多币种薪资（员工 `currency` 字段）。
- 薪资"草稿 / 已确认 / 已发放"状态防误改。
- 合同管理模块（期限、续签提醒）。
- 离职/入职流程（异动记录）。
- 移动端 PWA（添加到主屏、离线可用）。
- 集团版多组织汇总看板。
