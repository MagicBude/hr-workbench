# 产品审视与优化追踪

> 审视日期：2026-08-11  
> 基线版本：`cad878e`  
> 目标：把当前“功能完整的演示工具”提升为“可较放心管理真实内部数据的轻量 HR 系统”。

---

## 1. 审视结论

当前产品的花名册、考勤、薪资、看板和组织设置主流程已经形成闭环，视觉语言基本统一，设置中心也为后续扩展提供了稳定入口。下一阶段不应继续堆叠零散开关，而应优先解决以下三类问题：

1. **数据可信度**：考勤率、薪资个税、在职人数等口径必须可解释、可追溯。
2. **操作安全感**：真实 HR 数据需要防误删、自动快照、导入前备份和输入安全。
3. **大表可读性**：考勤、薪资表应强化冻结列、输入态、汇总区与桌面导航。

---

## 2. P0：数据正确性与安全（必须先做）

### 2.1 考勤率改为应出勤工时口径

现状：看板按 `出勤 ÷（出勤 + 事假 + 病假 + 缺勤）` 计算，未纳入年假、调休、迟到、早退和未录入，容易产生误导。

目标：

- 以组织工作日和员工在职区间计算“应出勤工时”。
- 展示应出勤、实际出勤、请假、缺勤、未录入五项。
- 看板出勤率统一为 `实际出勤工时 ÷ 应出勤工时`。
- 明确迟到/早退只影响异常统计，不把整个半天从出勤中移除。

验收：

- [ ] 节假日和调休上班日影响应出勤工时。
- [ ] 月中入职、离职员工只统计有效在职区间。
- [ ] 未填写考勤单独显示，不被当作出勤或请假。
- [ ] 看板和考勤汇总使用同一计算函数。

### 2.2 薪资区分估算、人工覆盖和发放状态

现状：个税采用固定起征点和 10% 演示税率；工资输入变化后，个税可能保留旧值。

目标：

- 明确标记“个税为演示估算，不构成正式税务结果”。
- 工资、补贴、奖金、加班费变化时重新估算个税。
- 手工改税后记录 `taxManual=true`，显示“人工覆盖”。
- 增加 `draft / confirmed / paid` 状态。
- 已确认或已发放记录锁定关键输入；解锁需二次确认。

验收：

- [ ] 收入变化会更新未人工覆盖的个税。
- [ ] 人工覆盖税额不会被普通刷新覆盖。
- [ ] 已确认/已发放工资不可直接编辑。
- [ ] 页面、导出文件包含核算状态。

### 2.3 员工生命周期与离职归档

现状：所有员工都计入“在职员工”；删除员工后关联考勤和薪资成为孤立记录。

目标：

- 增加 `employmentStatus`：`probation / active / suspended / departed`。
- 增加 `leaveDate`，保留历史记录。
- 默认操作改为“离职归档”，永久删除移入回收站。
- 花名册可筛选在职、试用、停薪、离职。
- 看板按统计月份计算当时在职人数。

验收：

- [ ] 离职员工历史考勤和薪资仍可查询。
- [ ] 默认花名册不混入已离职员工。
- [ ] 月中入离职影响当月应出勤。
- [ ] 永久删除前可从回收站恢复。

### 2.4 输入与导入安全

现状：姓名、组织名等内容在部分位置直接拼接 `innerHTML`；导入文件可携带不可信文本。

目标：

- 统一提供 `escapeHtml / escapeAttr`，或优先使用 `textContent`。
- 所有姓名、部门、组织、节假日名称进入 HTML 前转义。
- 导入数据执行 schema 校验、类型校验和长度限制。
- 备份文件增加 `schemaVersion`。

验收：

- [ ] `<img onerror=...>` 等文本只能作为普通文字显示。
- [ ] 畸形导入文件给出字段级错误，不破坏现有数据。

### 2.5 数据快照、回收站与恢复

目标：

- 每次破坏性操作前自动生成组织快照，保留最近 10 份。
- 导入前自动备份当前组织。
- 清空和永久删除采用回收站/快照恢复机制。
- 设置中心显示存储占用量和快照管理入口。
- 后续迁移 IndexedDB 或后端属于架构阶段，不在本轮强行引入。

## 3. P1：交互与视觉优化

### 3.1 花名册

- 新增员工表单默认收起，使用“新增员工”按钮打开弹窗。
- `0分钟` 显示为 `—` 或 `0`。
- 调休天/小时/分钟单位禁止窄屏折行。
- 员工状态使用轻量标签展示。
- 删除按钮降级为二级危险操作，优先提供“离职归档”。

### 3.2 考勤表

- 桌面筛选区改为紧凑工具栏，不让搜索框和部门选择占满两行。
- 汇总列保持统一宽度，支持折叠/展开汇总区。
- 固定姓名、部门、时段列；横向滚动时保留上下文。
- 增加状态图例和“未录入”视觉状态。
- 批量操作显示即将影响的人数、日期范围和撤销入口。

### 3.3 薪资表

- 固定姓名、部门列。
- 可编辑输入使用浅色背景，计算结果保持只读白底。
- 增加脏数据提示、保存反馈和状态筛选。
- 表头与导出字段保持同一顺序和同一命名。

### 3.4 导航与反馈

- 宽屏使用顶部/侧边模块导航，底部 Tab 仅用于移动端。
- 将原生 `alert / confirm / prompt` 逐步替换为统一弹窗和 Toast。
- 所有保存、导入、恢复、清空操作提供明确结果反馈。
- 设置中心保留当前四分区，后续增加搜索时仍按组织级作用域管理。

## 4. P2：工程维护与长期架构

### 4.1 模块级刷新

现状：任一修改调用 `window.__renderAll()`，所有模块重绘并重新绑定事件。

目标：

- 提供 `refresh("roster") / refresh("attendance") / refresh("payroll") / refresh("dashboard")`。
- 数据变更声明影响范围，只刷新必要模块。
- 保留 `renderAll()` 作为组织切换、导入恢复等全局场景入口。

### 4.2 存储访问收敛

- 业务模块不再直接操作 `localStorage`。
- 列宽、界面偏好、快照统一经过 `store.js` API。
- 为未来 IndexedDB/后端替换保留单一适配层。

### 4.3 自动化测试

最低测试集：

- 调休天/小时/分钟与分钟值互转。
- 工作日、节假日、入离职区间和应出勤工时。
- 加班行只能“加/空”，迟到早退开关联动。
- 调休余额、加班转调休比例和负余额。
- 薪资估算、人工税覆盖和状态锁定。
- 旧数据迁移、schemaVersion、快照恢复。
- HTML 转义和恶意导入文本。

### 4.4 文档同步

- README 功能列表与目录增加 `settings.js`、员工状态、快照等内容。
- SPEC 更新 9 种考勤状态、`restSeedMinutes`、动态调休余额和组织设置。
- ARCHITECTURE 修正“业务模块绝不直接读 localStorage”与当前实现的差距。
- 每次数据结构变化同步 `STANDARD.md` 和迁移说明。

## 6. 本轮边界

本轮在纯前端架构内完成可闭环的正确性、安全、体验和测试优化。以下事项保留在后续阶段：

- 后端多租户、账号、权限 RBAC、审批流和审计日志。
- 正式中国个税累计预扣算法及税务合规承诺。
- IndexedDB 大容量附件、云端备份和多端同步。
- 在线节假日服务、真实社保接口和财务系统对接。

这些事项需要新的数据服务和权限模型，不能仅通过增加前端开关安全完成。
